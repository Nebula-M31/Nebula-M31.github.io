Euler’s Circuit Theorem

（Seven bridges of Königsberg）

Eulerian Circuit：a closed walk cover all arcs.

Euler's Circuit Theorem

An undirected connected graph has an Eulerian circuit ⟺\Longleftrightarrow⟺ the degree of every node is even.

proof.

  • necessity：边的全覆盖 →\rightarrow→ 点的全覆盖；每个点：有进必有出 ⇒\Rightarrow⇒ 度为偶数。
  • sufficiency：
    • Lemma：undirected connected graph，every node’s degree is even ⇒\Rightarrow⇒ it contains a closed walk ⇒\Rightarrow⇒ it contains a cycle.
    • Induction：
      • GGG：undirected connected graph，∀\forall∀ nodes even degree
      • base：GGG with 2 edges has an Eulerian circuit
      • hypothesis：GGG with fewer than mmm edges has an Eulerian circuit
      • induction step：GGG with mmm edges
        1. 用 Lemma 找出一条 cycle CCC；
        2. G−C=G′G - C = G'G−C=G′；
        3. 对 G′G'G′ 的每个 component 用 hypothesis，可以得到不同的 Eulerian circuit；
        4. 把这些 Eulerian circuits 链接到 CCC；
        5. 形成一条 closed walk 就得到一个 Eulerian circuit。

Lecture 3

Complexity Analysis

1. Measuring Algorithm Efficiency

  • 计算资源 (Computing Resources)：执行算法所需的存储空间（Space Complexity）和运行时间（Time Complexity）。
  • 时间复杂度 (Time Complexity)：通常以“基本操作 (Basic Operations)”的次数来衡量。
    • 赋值 (Assignment)
    • 算术运算 (Arithmetic: 加减乘除)
    • 逻辑运算 (Logical: 条件判断、比较)
  • 示例：矩阵相加。两个 m×nm \times nm×n 矩阵相加，需要进行 mnmnmn 次加法和 mnmnmn 次赋值，总操作数为 2mn2mn2mn。通常写作 O(mn)O(mn)O(mn)。

2. Complexity Measures

  • 经验分析 (Empirical Analysis)：在大量实例上运行算法。
    • 优点：无需对算法进行理论分析。
    • 缺点：依赖各种外部因素，耗时。
  • 平均情况分析 (Average-case Analysis)：取所有实例的平均值。
    • 优点：在解决大量不同实例时具有指示性。
    • 缺点：依赖问题实例的分布，分析难度大。
  • 最坏情况分析 (Worst-case Analysis)：分析算法在最“坏”实例上的表现。
    • 优点：提供算法性能的决定性保证。
    • 缺点：可能过于关注病态情况 (Pathological cases)。

3. Problem Size & Polynomial Time

  • 问题规模 (Problem Size)：编码问题数据所需的比特数。例如网络流问题中，问题规模约为 mlog⁡n+mlog⁡C+mlog⁡U+nlog⁡Bm \log n + m \log C + m \log U + n \log Bmlogn+mlogC+mlogU+nlogB。
  • 多项式时间算法 (Polynomial-time Algorithm)：最坏情况复杂度是问题规模的多项式函数（如 n,m,log⁡C,log⁡Un, m, \log C, \log Un,m,logC,logU）。
    • 强多项式时间 (Strongly Polynomial-time)：复杂度不涉及 log⁡C\log ClogC 或 log⁡U\log UlogU（如 n2mn^2mn2m）。仅与问题规模中的组合结构有关，与数值大小无关。
    • 弱多项式时间 (Weakly Polynomial-time)：涉及 log⁡C\log ClogC 或 log⁡U\log UlogU（如 m+nlog⁡Cm + n\log Cm+nlogC）。
  • 指数时间 (Exponential Time)：如 2n,n!,nC,mnU2^n, n!, nC, mnU2n,n!,nC,mnU 等。

Data Structure Basics

Stacks and Queues

  • 栈 (Stack)：后进先出 (Last-In-First-Out, LIFO)。所有插入 (Push) 和删除 (Pop) 都在栈顶 (Top) 进行。
  • 队列 (Queue)：先进先出 (First-In-First-Out, FIFO)。在队尾 (Rear) 插入，在队首 (Front) 删除。

d-heap

1. 概念与基本操作 (Concept & Basic Operations)

  • 用途：存储并操作集合 HHH，每个元素 iii 有关联的实数 key(i)key(i)key(i)。常用于实现最短路问题（节点为 HHH，路径长度为 keykeykey）的算法（如Dijkstra算法）。

  • 7种基本操作：

    1. create(H): 创建一个空堆。
    2. insert(i, H): 插入元素。
    3. find-min(i, H): 找到最小键值的元素（通常返回根）。
    4. delete-min(i, H): 删除最小键值的元素。
    5. delete(i, H): 删除任意元素。
    6. decrease-key(i, value, H): 减小键值。
    7. increase-key(i, value, H): 增大键值。

2. 结构与性质 (Structure & Properties)

  • 生成规则：节点按深度值 (depth values) 递增的顺序添加，同一深度内从左到右添加。
  • 数学性质：
    1. 深度 kkk 的节点最多有 dkd^kdk 个。
    2. 深度 0 到 kkk 之间的节点总数最多为 (dk+1−1)/(d−1)(d^{k+1}-1)/(d-1)(dk+1−1)/(d−1) 个。
    3. 包含 nnn 个节点的 d-heap，其深度最多为 O(log⁡dn)O(\log_d n)O(logd​n)。
  • 堆序性质 (Order Property)：父节点的 key 小于等于每个后继节点的 key（key(i)≤key(j)key(i) \le key(j)key(i)≤key(j)）。因此根节点是全局最小。
  • 数组存储 (Array Storage)：d-heap 被存储为数组 DHEAP，并用 last 记录节点总数。为了快速定位元素，引入 Position 数组：position(i) = j（表示元素 iii 在数组中的位置是 jjj）。
完全 d 叉树 (Complete d-ary Tree)
  • 完全树 (Complete Tree)：除了最后一层外，其他层的节点都是满的，且最后一层的节点都集中在左侧。
  • d 叉树 (d-ary Tree)：每个节点最多有 ddd 个孩子。
  • 高度 (Height)：对于包含 nnn 个节点的完全 d 叉树，高度为 O(log⁡dn)O(\log_d n)O(logd​n)。
  • 为什么用完全树？：因为完全树没有“空洞”，所以可以极紧凑地直接存入数组中，不需要额外指针，节省空间且索引计算高效。

3. 数组存储与索引 (Array Storage & Indexing)

  • 数组内容：DHEAP = [7:5, 2:9, 3:8, 9:15, 5:21, 1:12, 4:16, 6:18, 8:29]，last = 9。
  • Position 例子：position(3) = 3, position(6) = 8。

  • 图例解释：

    • 黑色数字（圆圈内）：元素的键值 key(i)，代表这个点i在图中到目标点的最短路径长度。
    • 红色数字（左侧）：点在图中的编号 i（如节点 ID）。
    • 蓝色数字（右侧）：点在这个有根树中的位置 position(i)。

  • 数组对应关系：例如 7:5 意味着元素 7 的 key 是 5，在数组的第 1 个位置。

    索引计算公式（下标从 1 开始）

    • 找父节点 (Predecessor)：位置 iii 的父节点位置为 Pred(i) = ⌈(i-1)/d⌉。
      • 例：d=3d=3d=3，位置8的父节点在 ⌈7/3⌉=3\lceil 7/3 \rceil = 3⌈7/3⌉=3。
    • 找子节点 (Successors)：位置 iii 的子节点位置在 [id-d+2, ..., id+1] 之间。
      • 例：d=3d=3d=3，位置2的子节点在 {5, 6, 7}。
    • 通过元素找父节点流程：j = position(i) → k = Pred(j) → DHEAP(k)。

4. 核心调整机制

所有堆操作最终都归结为 O(1)O(1)O(1) 的 swap 操作。

  • 上浮 (Sift up)
    • 触发：key 变小（如 decrease-key、insert）。
    • 逻辑：不断与父节点比较，若比父节点小则交换，直到恢复堆序或到达根。
    • 复杂度：仅与父节点比较，树高 O(log⁡dn)O(\log_d n)O(logd​n)，故为 O(log⁡dn)O(\log_d n)O(logd​n)。
  • 下沉 (Sift down)
    • 触发：key 变大（如 increase-key、delete-min）。
    • 逻辑：不断与所有子节点比较，找出最小的子节点，若自己比它大则交换，直到恢复堆序或叶子。
    • 复杂度：每层需比较 ddd 个子节点，树高 O(log⁡dn)O(\log_d n)O(logd​n)，故为 O(d⋅log⁡dn)O(d \cdot \log_d n)O(d⋅logd​n)。
